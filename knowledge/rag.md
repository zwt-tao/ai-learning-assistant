# RAG 基础

## 什么是 RAG

RAG 全称 Retrieval-Augmented Generation，即检索增强生成。它是一种让大模型能够回答私有知识库问题的技术。RAG 的核心思想不是把所有知识塞进模型，而是先检索相关知识，再把知识和问题一起发给模型。

## 为什么需要 RAG

大模型本身只知道训练数据中的通用知识。对于公司内部文档、个人笔记、最新资料，模型一无所知。直接把所有文档塞进模型既超字数又贵。RAG 解决的就是"让模型基于你提供的资料回答"的问题。

## 完整 RAG 流程

RAG 分为两个阶段。离线阶段：读取文档、切成 Chunk、生成向量、存入向量数据库。在线阶段：用户提问、把问题转成向量、在向量库中找最相似的几个 Chunk、把这些 Chunk 和问题拼成 Prompt、发给大模型、返回答案。

## Chunk 切分

Chunk 是把长文档切成小片段。chunkSize 决定每个片段多大，overlap 决定相邻片段重叠多少。chunk 太大检索不精准且费 token，太小语义不完整。overlap 防止重要句子被从中间切断。

## Embedding 向量

Embedding 是把文字转换成一串数字（向量）。意思相近的文字，向量距离也近。这样计算机就能比较两段文字的语义相似度，而不是只匹配关键词。Embedding 由专门的 Embedding 模型生成。

## 向量数据库

向量数据库专门存储和检索向量。常见的有 Chroma、Pinecone、Milvus。用户提问时，把问题也转成向量，在数据库中找距离最近的几个 Chunk，这就是相似度检索。

## RAG 与多轮对话的区别

多轮对话的 Context 是用户之前说过的话，目的是让模型记住对话历史。RAG 的知识来自外部文档，目的是让模型基于私有资料回答。两者可以同时使用：模型既记得你之前说过什么，也能查阅你的知识库。
